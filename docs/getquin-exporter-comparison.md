# เปรียบเทียบ Getquin Portfolio Exporter กับ Investment Tracker

วันที่ตรวจ: 2026-10-06  
แหล่งหลัก: [aybruhm/getquin-portfolio-exporter](https://github.com/aybruhm/getquin-portfolio-exporter/tree/af403b9fb90d460dc9a12b801fce01502c787d29) ณ commit `af403b9`.

## สรุป

ควรหยิบแนวคิด **นำเข้า/ส่งออก transaction แบบมี mapping, ตรวจข้อมูลก่อนเขียน และทำงานในเครื่อง** มาใช้ ไม่ควรยก exporter มาแทนระบบพอร์ต: README ของ exporter ระบุว่ามันแปลง Getquin JSON ไปเป็น CSV/XLSX ส่วนโปรเจกต์นี้มี portfolio engine, Smart-DCA v2 และ portfolio snapshots อยู่แล้ว ([exporter README](https://github.com/aybruhm/getquin-portfolio-exporter/blob/af403b9fb90d460dc9a12b801fce01502c787d29/README.md), [README ของโปรเจกต์](../README.md)).

สถานะโปรเจกต์ปัจจุบันยังไม่มี transaction import/export แต่เพิ่มการ export Smart-DCA training samples แบบ JSONL สำหรับ owner แล้ว ข้อมูลนี้เป็น input/recommendation ของระบบ ไม่ใช่ transaction history หรือ outcome การลงทุน จึงยังไม่ทดแทนความต้องการ export ธุรกรรมเพื่อ backup หรือย้ายไป platform อื่น

## ช่องว่างและโอกาสของโปรเจกต์นี้

- **ความสามารถหลักต่างกัน:** tracker มีการคำนวณพอร์ต, ผลตอบแทน/benchmark, snapshots และ risk-aware Smart-DCA; ส่วน exporter เน้นย้ายข้อมูล transaction ระหว่างรูปแบบ จึงควรเสริม portability ให้ tracker ไม่ใช่แทนที่ analytics ([README](../README.md), [snapshot API](../backend/src/routes/snapshots.js), [Smart-DCA plan](../Smart-DCA-v2-logic-plan.txt)).
- **ยังไม่เห็นช่องทาง transaction import/export:** README ระบุการสร้าง transaction และ API สำหรับ list/create แต่ไม่ระบุ import/export; route ที่ตรวจพบมี list/filter, create, update และ delete ไม่มี bulk import หรือ download route ([API overview](../README.md), [transactions route](../backend/src/routes/transactions.js)).
- **currency model รองรับแล้ว แต่ยังมีขอบเขต:** transaction เก็บ `currency` และ `fx_rate`; cash ledger/snapshots รักษายอดแยกสกุลและแปลงเป็น USD ด้วยเรทล่าสุด ส่วนต้นทุนหลักทรัพย์และ `netTotalInvested` ใช้เรทตอนทำรายการ ระบบใช้ currency เดียวร่วมกันกับราคา/fee/tax ต่อ transaction ยังไม่ได้แยก `price_currency`, `costs_currency`, `taxes_currency` แบบ Getquin ([schema](../backend/src/db.js), [FX API](API-GATEWAY.md), [README: currency/history](../README.md)).
- **มีจุดเริ่มต้นที่นำไปต่อได้:** tracker มี transaction CRUD และ filter ตามวัน/ประเภท/action/broker อยู่แล้ว จึงเพิ่ม import preview/validation ได้โดยไม่ต้องเปลี่ยน flow การคำนวณพอร์ต ([transactions route](../backend/src/routes/transactions.js), [README](../README.md)).

## ข้อเสนอแนะเรียงลำดับ

1. **เพิ่ม transaction export สำหรับ backup ก่อน** — ให้ดาวน์โหลด CSV และ JSON โดยรองรับตัวกรองที่มีอยู่ (ช่วงวัน, action, broker) นี่เป็นงานต่อยอดตรงกับ GET `/api/transactions` และช่วยย้าย/เก็บข้อมูลโดยไม่เพิ่มความเสี่ยงให้ DCA; XLSX เป็นตัวเลือกทีหลังหากมีความต้องการจริง ค่า export ควรเก็บ `currency` และ `fx_rate` ตาม transaction ต้นฉบับ ([transactions route](../backend/src/routes/transactions.js), [CSV/XLSX จาก exporter](https://github.com/aybruhm/getquin-portfolio-exporter/blob/af403b9fb90d460dc9a12b801fce01502c787d29/README.md)).
2. **กำหนดขอบเขต currency ของ import** — model ปัจจุบันใช้ currency เดียวต่อ transaction ร่วมกันกับจำนวนเงิน, fee และ tax; หาก input แยกสกุลของราคา/ค่าใช้จ่าย/ภาษี ต้องเพิ่ม mapping ที่ชัดเจนหรือปฏิเสธรายการนั้นใน preview อย่าเดา FX rate หรือแปลงเงียบ ๆ ตอน import ([Getquin transaction type](https://github.com/aybruhm/getquin-portfolio-exporter/blob/af403b9fb90d460dc9a12b801fce01502c787d29/core/src/types/transaction.ts), [schema](../backend/src/db.js), [FX API](API-GATEWAY.md)).
3. **เพิ่ม import แบบ adapter และ preview ก่อน commit** — เริ่มจาก Getquin JSON หรือ statement/CSV ของ Dime; map วันที่, symbol, action, units, price, fee/tax, currency และ `fx_rate` ให้เป็น transaction schema ของ tracker แสดงรายการที่อ่านไม่ได้/ไม่รองรับและให้ผู้ใช้ยืนยันก่อนบันทึก เพิ่ม source ID หรือ fingerprint เพื่อกันรายการซ้ำใน import รอบถัดไป แนวคิด mapping config ของ exporter เหมาะเป็นต้นแบบ แต่ deduplication ใน upstream ยังอยู่ใน roadmap ไม่ใช่ความสามารถที่ยืนยันว่าทำแล้ว ([CLI input contract](https://github.com/aybruhm/getquin-portfolio-exporter/blob/af403b9fb90d460dc9a12b801fce01502c787d29/cli/src/commands/transform.ts), [mappings](https://github.com/aybruhm/getquin-portfolio-exporter/tree/af403b9fb90d460dc9a12b801fce01502c787d29/mappings), [roadmap](https://github.com/aybruhm/getquin-portfolio-exporter/blob/af403b9fb90d460dc9a12b801fce01502c787d29/README.md)).
4. **เลื่อนหน้าแก้ mapping แบบทั่วไปไว้ก่อน** — เริ่มด้วย adapter ที่เขียนและทดสอบในโค้ดสำหรับ 1–2 format แล้วค่อยสร้าง UI ถ้าต้องรองรับหลาย broker/ปลายทางจริง เพราะ tracker ยังเป็น static frontend; UI สร้างภาระด้าน validation, versioning และ support เพิ่ม ([frontend/architecture](../README.md), [Mapping Creator upstream](https://github.com/aybruhm/getquin-portfolio-exporter/blob/af403b9fb90d460dc9a12b801fce01502c787d29/mapping-ui/src/routes/%2Bpage.svelte)).
