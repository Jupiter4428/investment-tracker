# SMART-DCA V2 — LOGIC / FUNCTION PLAN v1.1

## เป้าหมาย

สร้าง Smart-DCA v2 โดยต่อยอดจาก investment-tracker เดิม

หลักการ:

* legacy dcaEngine.js ถูกถอดออกเมื่อ Smart-DCA v2 ครอบคลุมเส้นทาง allocation แล้ว
* ไม่ AUTO SELL
* ใช้เงินใหม่เพื่อ DCA / Rebalance เข้า Target
* ลดหรือหยุด DCA หุ้นที่ overweight
* ใช้ Hard Max เป็นข้อจำกัดสูงสุด
* หุ้นที่ถือจริงแต่ไม่มี Target ต้องไม่ถูกนำไปเพิ่ม allocation โดยอัตโนมัติ
* Pure functions ต้องมี unit tests ตั้งแต่เริ่มพัฒนา

3. NOT_IN_TARGET

---

หุ้นที่มีอยู่จริงในบัญชี แต่ไม่ได้อยู่ใน Target Portfolio
เช่น:

* IONQ
* SPCX
* FN

ให้สถานะ:

NOT_IN_TARGET

กฎ:

* targetWeight = 0
* hardMaxWeight = 0
* DCA allocation = 0
* ไม่ซื้อเพิ่มอัตโนมัติ
* ไม่ AUTO SELL
* ไม่รวมในการจัดสรร DCA ปกติ
* แสดงแยกใน Dashboard
* แสดงสถานะ HOLD หรือ REVIEW ตาม risk/data/fundamental condition
* หากต้องการให้หุ้นกลับเข้าสู่ allocation logic ต้องเพิ่ม Target Weight อย่างชัดเจนใน config

สำคัญ:

ไม่ใช้:
hardMaxWeight = currentWeight

เพราะ currentWeight เปลี่ยนตามราคาตลาดและอาจทำให้ risk/allocation logic ผิดความหมาย

ตัวอย่าง:

IONQ
currentWeight = 3%
targetWeight = 0%
hardMaxWeight = 0%
status = NOT_IN_TARGET
DCA = 0

4. SCORING ENGINE

---

ไฟล์:
backend/src/services/smartDcaV2/scoring.js

Functions:

clamp(value, min, max)

* จำกัดคะแนนให้อยู่ใน 0–100

safeNumber(value, fallback)

* ป้องกัน NaN / undefined / invalid number

underweightScore(currentWeight, targetWeight)

* วัดว่าหุ้นต่ำกว่า Target มากแค่ไหน
* Underweight มาก = คะแนนสูง
* Overweight = คะแนนต่ำ

valuationScore(ticker, pe, valuationReference)

* เปรียบเทียบ P/E กับ valuation reference
* เป็น relative valuation signal
* ไม่ถือว่าเป็น intrinsic/fair value จริง

rsiScore(rsi)

* RSI ต่ำ = accumulation score สูง
* RSI สูง = score ลดลง
* RSI สูงไม่ใช่ SELL

trendScore(price, ema26)

* ราคาต่ำกว่า EMA26 = score สูงขึ้น
* ราคาสูงกว่า EMA26 มาก = score ลดลง

macdScore(macdData)

* ใช้ MACD / signal / histogram
* Bearish / negative histogram = accumulation score สูงขึ้น
* Bullish = ลด score บางส่วน
* ไม่สร้าง SELL action โดยตรง

volatilityScore(annualizedVolatility)

* volatility ที่สูงขึ้นสามารถเพิ่ม accumulation opportunity
* extreme volatility ต้องผ่าน risk gate

calculateCompositeScore(scores)

* รวมคะแนนตาม SCORE_WEIGHTS
* ผลลัพธ์ 0–100

scoreStock(data)

* รวมทุก factor
* คืน stock score
* ระบุ currentWeight
* targetWeight
* hardMaxWeight
* isOverweight
* isOverMax
* status

* deterministic
* อธิบายได้

8. CONSTRAINED ALLOCATION

---

Hard Max ต้องมีผลเหนือ score

ลำดับ:

Score
↓
Initial Allocation
↓
Hard Max Constraint
↓
Remove blocked stocks
↓
Calculate remaining budget
↓
Redistribute
↓
Check Hard Max again
↓
Repeat until:

* budget exhausted
* หรือไม่มี stock ที่มี capacity เหลือ
  ↓
  Cash Remaining

ห้ามทำ:

initial allocation
→ normalize ครั้งเดียว
→ จบ

เพราะอาจทำให้หุ้นอื่นทะลุ Hard Max หลัง redistribution

9. ALLOCATION INVARIANTS

---

หลัง allocation เสร็จ ต้องเป็นจริงเสมอ:

1. allocation >= 0

2. allocation <= available budget

3. stock allocation <= remaining Hard Max capacity

4. NOT_IN_TARGET allocation = 0

5. STOP_BUY allocation = 0

6. total allocated <= budget

7. ห้ามมี stock ใดทะลุ Hard Max

8. หากไม่มี capacity เหลือ:
   remaining budget → cash

9. RSI + PORTFOLIO STATE

---

Portfolio state ต้องมี priority เหนือ indicator

กรณี:

Underweight มาก + RSI oversold
→ ACCUMULATE

Underweight มาก + RSI neutral
→ BUY

Underweight มาก + RSI overbought
→ BUY / DCA ในจำนวนที่ลดลง

Near Target + RSI overbought
→ HOLD / PAUSE

Overweight + RSI neutral
→ PAUSE

Overweight + RSI overbought
→ PAUSE

Current >= Hard Max + ทุก RSI
→ STOP_BUY

หลักการ:

RSI สามารถลด priority
แต่ RSI ไม่สามารถ override Hard Max

11. ACTION ENGINE

---

Actions:

ACCUMULATE

* score สูงมาก
* underweight
* risk gate ผ่าน

BUY

* score สูง
* eligible

DCA

* score กลาง
* ยังเหมาะกับ regular accumulation

HOLD

* score ต่ำ/กลาง
* ไม่จำเป็นต้องเพิ่ม allocation

PAUSE

* overweight
* หรือ RSI/technical condition ไม่เหมาะกับการเพิ่ม DCA
* ไม่มี allocation ใหม่

STOP_BUY

* currentWeight >= hardMaxWeight
* hard rule
* ไม่ขาย

NOT_IN_TARGET

* targetWeight = 0
* DCA = 0
* แสดงแยก

REVIEW

* data problem
* portfolio risk สูง
* fundamental/data deterioration
* unusual condition

12. ACTION PRIORITY

---

กฎ priority:

1. Data invalid
   → REVIEW

2. Portfolio risk BLOCK
   → จำกัดหรือหยุด allocation ตาม risk policy

3. NOT_IN_TARGET
   → NOT_IN_TARGET
   → DCA = 0

4. Current >= Hard Max
   → STOP_BUY

5. Overweight
   → PAUSE / HOLD

6. Underweight + technical favorable
   → ACCUMULATE / BUY

7. Underweight + technical unfavorable
   → BUY / DCA ลดลง

8. Near Target
   → DCA ปกติหรือลดลง

Hard rules มีสิทธิ์เหนือ score
